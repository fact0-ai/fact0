---
title: "How Fact0 runs"
description: "One owner, three local services and explicit capture destinations."
---

Fact0 consists of a Go API, a Next.js dashboard and PostgreSQL. Docker Compose starts a tracked migration job before the application services.

The browser uses the application origin. The web server proxies authenticated API calls to the private API service. SDKs and the Claude collector use your explicitly configured host-accessible API URL. The default exposed ports are bound to localhost.

## Supported capabilities

- Executions, spans, errors, DAGs, timelines and replay of recorded history.
- Basic usage and cost estimates from available telemetry and bundled pricing.
- Separate audit records with per-tenant hash chains, search and verification.
- Authenticated PDF/evidence exports signed by a persistent instance key.
- Python and Claude Code capture workflows.

## Release boundaries

One owner/workspace, password login, fresh installations and synchronous ingestion. Automatic data expiration is disabled. Billing, hosted administration, invitations, Spotlight, email, alert webhooks, public sharing, governance enforcement and OTLP are unavailable in this release.

No Google OAuth, AWS, Neon, Redis or mail configuration is required. Package installation and initial collector downloads require network access; the core has no required outbound analytics or pricing synchronization.
